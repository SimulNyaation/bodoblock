# 긴 영수증 테스트 — 2026-09-07

이 문서는 이전 구현의 측정 기록이다. 현재는 축소 PNG가 아닌 고정 해상도 스트리밍 PNG + 임계 초과 SVG를 사용한다. 최신 수치와 172,800개 검증은 [고해상도 한 장 저장](highres-export.md)을 참고한다.

## 사진 저장 전환 후 추가 검증

현재 저장 형식은 아래 과거 SVG 측정과 달리 PNG다. `scripts/photo-check.js`로 실제 PNG 시그니처·디코딩·저장 완료 초기화·취소 유지(네이티브 메뉴 API 모의)를 확인했다. PC Chrome 측정: 600개 340×8,815 / 1.48MB, 1,200개 241×12,428 / 1.90MB, 3,600개 106×16,384 / 2.00MB. 최대 300만 픽셀을 유지한다. 실제 iOS 메뉴/사진 앱 저장은 이 테스트로 검증하지 못한다. 매우 긴 사진은 폭도 축소되므로 세부 선명도가 낮아진다.

## 과거 SVG 원본 측정

Windows PC의 Headless Chrome 152, 뷰포트 390×844에서 측정했다. 실제 휴대폰이나 1시간 연속 실행 테스트가 아니다. `stressBoard`로 기록을 미리 만든 뒤 실제 Export/스크롤/저장/초기화 UI를 실행한다. 기본 배치는 가로 블록을 6칸 폭에 빈틈 없이 채우며 흰 타일은 없다. `layout=tower`는 한 열로 쌓아 길이 부담을 높인다. 실제 플레이의 회전·빈 공간·흰 타일에 따라 결과가 달라진다.

| 기록 | 1시간 환산 가정 | 저장 SVG 바이트 | SVG 크기 | 미리보기 표시 대기(2회 측정) |
| --- | --- | ---: | --- | --- |
| 600개 | 6초당 1개 | 1,307,220 | 344×8,912 | 37–51ms |
| 1,200개 | 3초당 1개 | 2,694,289 | 344×17,712 | 65–67ms |
| 3,600개 | 1초당 1개 | 8,287,089 | 344×52,912 | 196–205ms |
| 3,600개 한 열 | 1초당 1개 | 8,643,219 | 344×158,512 | 183–198ms |

시간은 클릭 이벤트 시작부터 두 번째 requestAnimationFrame까지의 근사치다. SVG 생성과 DOM 삽입은 메인 스레드에서 동기 실행된다. 스크롤 60프레임 표본의 p95 간격은 약 18–20ms였다. 모든 케이스에서 끝까지 스크롤·SVG 다운로드·저장 후 초기화를 확인했다. 1,200개에서 추가 20회 실제 키보드 배치 후 1,220개 영수증도 확인했다. JS 오류는 없었다. 다운로드 파일은 `output/playwright/stress-*.svg`, 화면은 같은 경로의 PNG다.

SVG의 크기는 압축하지 않은 실제 다운로드 크기다. 스크립트의 `bytes`는 DOM이 직렬화한 문자열 크기라 저장 원본보다 조금 크다. PNG 파일 크기는 측정하지 않았다. 가령 344×52,912 RGBA 비트맵 하나만 약 72.8MB이며 임시 복사본·고해상도 배율을 적용하면 메모리가 더 필요하다. 이를 PNG 압축 파일 용량과 혼동하지 않는다.

## 휴대폰에서 직접 확인

같은 Wi-Fi에서 개발 서버 주소 뒤에 아래 쿼리를 붙인다.

- `/?stress=600`
- `/?stress=1200`
- `/?stress=3600`
- `/?stress=3600&layout=tower`

일시정지 → Export → 끝까지 스크롤 → 이미지 저장을 확인한다. 이어서 타일을 놓는 것도 가능하다. 주소를 새로고침하면 테스트 기록이 다시 생성되지만, 저장 버튼은 정상적으로 빈 게임으로 초기화한다. 일반 주소는 영향을 받지 않는다. 최대 7,200개로 제한하며 `import.meta.env.DEV` 분기로 프로덕션 빌드에서는 테스트 진입 코드를 제거한다.

재실행: `npx.cmd --yes --package @playwright/cli playwright-cli -s=fable run-code --filename scripts/stress-check.js`

이 검증만으로 실제 1시간의 발열·배터리·누적 메모리 누수·iOS 저장 호환성을 보장하지 않는다. 실제 기기 연속 플레이는 추가 확인이 필요하다. 이번 변경에는 영수증 포맷 최적화나 PNG 변환을 포함하지 않았다.

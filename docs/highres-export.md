# 고해상도 한 장 저장 / 세션 상한

## 현재 구현

- 사용자 배치 상한: 172,800개 = 0.5초당 1개 × 24시간. 흰 자동 타일 제외. 개수 상한이며 실제 24시간 타이머나 초당 2개 속도 제한은 아니다.
- PNG: 가로 688px 고정, 원본 SVG 대비 2배 배율. 32,000,000픽셀 또는 세로 65,536px를 넘으면 SVG로 전환한다. 경계 값은 포함하며 초과부터 전환한다. PNG 생성 실패/CompressionStream 미지원 시에도 안내 후 SVG로 전환한다.
- 내부 렌더링: 688×256 캔버스 하나를 재사용하여 영역별 SVG를 그린다. RGB Sub 필터 → 하나의 연속 zlib 스트림 → 여러 IDAT 청크를 기록한다. 최종 결과는 단일 PNG다. 원본 전체의 대형 캔버스나 최종 이미지를 다시 디코딩하지 않는다. 압축 결과는 File 생성을 위해 메모리에 보관한다.
- SVG: 세 가지 공유 윤곽(가로/세로/흰 타일)만 정의하고 각 타일은 위치·색·참조만 기록한다. 1,024개씩 나눠 파일을 구성하고 이벤트 루프를 양보한다. 사진 앱이 아닌 파일 저장임을 안내한다.
- 미리보기: 전체 높이의 스크롤 공간 + 현재 화면 주변 SVG만 렌더링한다. 행별 버킷으로 검색하며 17만 개 DOM을 생성하지 않는다. 전체 영역 drop-shadow는 제거했다.
- 취소: AbortController로 생성 취소/리소스 해제. PNG 네이티브 메뉴 취소는 기록 유지. SVG는 다운로드 요청 후 초기화하며 실제 파일 저장 완료는 브라우저에서 확인할 수 없다.

균일 가로 블록 테스트 배치의 결과다. 실제 회전·틈·흰 타일 수에 따라 높이/크기가 달라진다. 최대치에서 미리보기 DOM은 약 63개 use로 제한되고 0/25/50/75/100% 스크롤 위치를 확인했다. 마지막 172,800번째 배치 성공, 다음 배치 차단, Export 유지, 저장 후 초기화를 확인했다. 생성 중 취소·재진입, 네이티브 저장 취소/완료(모의)도 확인했다.

짧은 혼합 패턴(회전과 흰 타일 포함) PNG를 원본 전체 렌더링과 비교: 5,459,968개 채널 중 2 초과 오차가 320개(0.006% 미만), 최대 14/255. 구간 렌더링의 미세한 안티앨리어싱 차이가 있으며 육안 경계선/누락은 발견하지 못했다. PNG 청크 CRC, 연속 zlib 스트림, 잘린 입력 거부는 단위 테스트로 확인했다.

재실행: `scripts/export-check.js`, `scripts/receipt-visual-check.js`를 Playwright CLI run-code로 실행한다. 산출물: `output/playwright/export-*`, `receipt-highres-detail.png`.

실제 iPhone 사진 앱에서 모든 길이의 확대·저장을 보장하지는 않는다. 스트리밍은 생성 메모리를 줄일 뿐 사진 앱의 디코더/표시 한계를 제거하지 않는다. SVG도 외부 뷰어는 전체 문서를 처리할 수 있어 앱 내부의 가상 스크롤보다 느릴 수 있다. 24시간 연속 발열/배터리/누수 테스트는 하지 않았다.

## 자동 플레이 방지 검토 (미구현)

현재는 서버·계정·랭킹·보상이 없는 로컬 게임이다. 사용자 기기의 코드/상태를 신뢰할 수 없으므로 AI 여부나 인간 플레이를 확실히 증명할 수 없다. 자동 낙하 자체가 정식 규칙이며, 단순한 일정한 간격을 부정 사용으로 판정하면 정상 플레이도 오탐한다.

- 로컬 완화: 비정상 연타·중복 입력 억제, 합법적인 이동/착지 검증, 세션 상한. 현재 충돌/착지/상한은 코어에서도 검증한다. isTrusted는 단순 dispatchEvent를 구분하는 단서일 뿐 인간 인증이 아니다. 난독화와 숨긴 클라이언트 키는 보안 경계가 아니다.
- 권장하지 않음: 반복 CAPTCHA, 손 떨림/규칙적 제스처를 기준으로 즉시 차단, 접근성 입력을 일괄 금지. 조용한 게임 경험을 훼손하고 오탐 우려가 크다.
- 향후 서버/랭킹/보상 도입 시: 서버가 발급한 세션과 서버 시각으로 속도·이벤트 순서·규칙을 검증하고 검증된 기록만 공개한다. 앱 무결성 검증은 보조 수단이며 인간 조작을 증명하지 않는다. 서버 비용·온라인 의존성·개인정보 처리 검토가 추가로 필요하다.
- 로컬에서 생성한 사진은 외부 프로그램으로도 재현할 수 있어 사진만으로 인간 플레이를 인증할 수 없다.

근거: [MDN isTrusted](https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted), [Apple App Attest](https://developer.apple.com/documentation/devicecheck/establishing-your-app-s-integrity), [Android Play Integrity](https://developer.android.com/google/play/integrity/overview).
